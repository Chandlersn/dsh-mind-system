## 2. 已实现主线

[调度器](../packages/dsh-execution-runtime/src/scheduler.js)只使用可信原生代码登记的模板与Verifier。任务输入不能提交可执行回调或替换授权。任务与候选按schema生成不可改快照；每个候选要绑定模板版本、必需前置条件、指定后置条件与工具副作用。规则主路径只选择唯一准入候选；提供者判别只接收已准入集合。

[准入](../packages/dsh-execution-runtime/src/admission.js)检查显式scope、工作区、工具授权、作用域内可见定义和宿主实际支持的参数schema。参数不能通过省略检查器获准。候选的副作用必须等于可信模板的工具声明，避免把写操作降成读操作后获得错误的失败/降级语义。约束和负向检查支持显式回调，但本轮没有接活动valves库。

[执行适配器](../packages/dsh-execution-runtime/src/executor.js)只调用公开`ToolRuntime.execute`，用不可改的显式Agent与调度器授权保持同一身份；保留root与真实parent token。每次调用有独立host ID。最前置的本次调用绑定钩子锁住身份、参数引用与token，信号保留宿主融合能力；普通pre/around包装器不能替换已准入参数。派发前的条件检查在真实允许派发阶段再做一次。没有经过本次派发钩子的成功回执不是成功证据。

[存储](../packages/dsh-execution-runtime/src/store.js)把结果、独立验证、下一业务游标与事件放在同一SQLite事务。注入事件写入失败时，它们全部回滚，未结动作保留。正常多步任务的最后游标同样与完成结果一起提交。

[JSON模板](../packages/dsh-execution-runtime/recipes/json-normalize.js)将准备、候选生成、两次前置检查和Verifier读取接入计量的只读I/O。实际写入仍经登记的宿主工具；测试工具使用独占创建。Verifier读取源文件及产物后比较目标事实，不消费工具返回中的`success`或`verification`字段。

## 3. 预算、截止与停止

增加独立的`maxIoOperations`，默认100；原工具调用上限20保持不变。计量对象是逻辑文件能力调用，不是内核系统调用。I/O、判别请求与工具意图均在执行前持久化预留，失败不归零；Verifier额度在业务派发前预留，剩余额度不返还，实际成功读取另有观察事件。现有阶段0数据可补齐新列，缺少新维度的旧任务按有界默认值计算。

正常JSON任务的测试事实为：1个动作尝试、1个公开工具调用、24个计费I/O单位、0判别请求、0分析调用。24包含5个预留验证I/O；这不是24次内核访问，也不是提供者性能数字。

截止使用墙钟与进程内单调时间共同检查；墙钟回拨不能延长当前运行。取消传播到公开工具管线并等待收敛；不宣称可强杀不响应信号的任意原生回调。若副作用发生后截止或验证不可得，状态进入`reconciling`，不把结果标成completed或自动重放。连续三次没有进展则停止至`waiting_analysis`，阶段1不会自行调用尚未接入的分析器。

## 4. 可失败的验证

最终整包命令：

```powershell
node --test --test-reporter=spec packages/dsh-execution-runtime/test/*.test.js
```

结果：171 tests / 171 pass / 0 fail / 0 skipped，退出码0。其中新增/扩展的准入44、执行适配器18、调度器38、预算/游标事务3项；阶段0既有68项同轮通过。

关键正反控包括：

- 正常JSON目标独立验收；工具返回伪造成功但磁盘内容错误时进入等待分析，不完成。
- 真实pre拒绝零工具副作用；post失败发生在文件已写之后时冻结，外部写入仍为1。
- 第一次准入后修改源文件，派发时第二次准入拒绝，写入为0。
- 普通包装器在派发检查前/后替换参数、名称、Agent或parent时不能改变真实动作；短路成功缺少本次钩子证据时保持未知。
- 两个不同Agent的准入/执行组合在任何模板读取前拒绝；已绑定执行Agent不能重写。
- 多步任务完整推进；尝试上限保留已完成游标和累计次数；三次无进展停止；I/O、工具、判别请求临界值阻止额外动作。
- 提供者失联时，显式唯一读规则继续；无规则、写规则、预算耗尽都不执行任意替代动作。本地HTTP成功路径完整走协议客户端与真实工具管线。
- prepare/candidates/provider/verifier/advance抛出null或undefined时，持久记录正常进入停止或核对状态，不留下running孤儿。
- 事务事件失败使结果、游标与状态一起回滚；旧任务新增预算有界；只读I/O拒绝可截断文件的flag，源内容保留。

变异验证分别运行[核心脚本](../packages/dsh-execution-runtime/scripts/verify-core-mutations.mjs)与[阶段1脚本](../packages/dsh-execution-runtime/scripts/verify-phase1-mutations.mjs)。两者要求原始基线退出0、每个变异语法有效且指定断言变红，拒绝把导入/语法错误当作抓住回归。阶段1覆盖：忽略二次准入、副作用降级、Verifier错绑、判别预算绕过、删除参数绑定、接受无钩子成功、混用调用者、空异常处理崩溃、游标未提交。最终结果：阶段1基线退出0，9/9变异被各自指定断言检出；阶段0核心基线退出0，4/4变异检出。两组验证命令均退出0。

## 5. 审查后的实质修正

只读审查识别并促成三项修正：宿主参数对象虽深冻结但引用仍可替换，因此增加本次调用的参数/身份绑定；任意抛出值需null安全规范化，否则异常处理自身会失败并留下running记录；准入Agent与执行Agent必须同一，不能分别消费两套作用域。三项均有反例，不以单纯“测试全绿”代替边界检查。

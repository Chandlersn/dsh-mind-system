## 三、一次任务的实际流转

```
调用方描述任务
  │
  ▼
runtime_execute(goal, recipe spec, inputs)
  │
  ├─ 检查 recipe.allowedTools ⊆ mount 允许的工具       ← 不能自己扩权
  ├─ 生成 recipe（校验 spec 白名单、效应表只能来自宿主）
  ▼
scheduler.run(task)
  │
  ├─ 取租约（fence 递增，旧写者立即失效）
  ├─ prepare → 写入 state {step:0}
  ▼
  ┌──────────────────────────────────────────┐
  │ 循环（直到完成 / 无候选 / 无进展 / 预算尽）│
  │                                          │
  │  candidates(state) → 当前步动作            │
  │     ↓                                    │
  │  准入：范围/效应/schema/前置条件           │
  │     ↓                                    │
  │  派发（经宿主管线）→ 工具真实执行           │
  │     ↓                                    │
  │  验证（按步骤选原语，读回产物）            │
  │     ↓                                    │
  │  advance → 计算下一步（含分支条件求值）     │
  │     ↓                                    │
  │  记录检查点（验证通过才写）                │
  └──────────────────────────────────────────┘
  │
  ├─ 失败 → 异常包 → 分析 → 四条分支之一 → 再次准入
  │            └→ 修复结果入 pattern 证据
  ▼
完成 / 待人工 / 待核对
```

## 四、当前真实卡点（按严重度排序）

```
①  未部署                              ← 最严重
   运行时只在隔离树。你日常 DSH 里没有它。
   后果：真实样本永远为 0，自循环永远不会自己转。
   解除条件：把 runtime 合进原仓库 + 构建 + 你授权改 junction。
   ⚠ 需要你明确授权（会动到你正在用的环境）。

②  核心能力仍靠外部模型判断（Jev 未接通）
   DSH_JEV_ENDPOINT / DSH_JEV_MODEL / DSH_JEV_API_KEY 全为空。
   现状：规则路径可跑（确定性选择器 + 协议 fixture），
        但「异常时调用推理模型」这一半从未真实跑过。
   后果：双循环里的「慢循环」目前是设计而非实测。

③  验收原语只有 3 个
   exact_bytes / line_set / structure
   缺：字段值由输入派生（关系型判据）、命令退出码、严格 schema 校验。
   后果：稍复杂的任务描述不出可验证的验收条件。

④  真实任务样本 = 0
   活动库 ~/.dsh/execution-runtime/runtime.sqlite 不存在。
   阈值（3 独立任务）与聚合逻辑都在，但没有数据。

⑤  阶段五对照实验未做
   DR-17/18：三组对照（既有循环 / 纯规则 / 规则+Jev）、P50/P95、成本、漏判率。
   需要真实任务集。
```

## 五、方向判断：哪些是对的，哪些需要你定

### 已经验证成立的设计

| 设计 | 为什么对 |
|---|---|
| **验收与执行分离** | 模型决定「怎么做」，不能决定「算不算成功」 |
| **闭合词汇表** | 验收原语、分支条件、修复分支都是闭合的，防止自证循环 |
| **单写者租约 + 围栏** | 并发下不会有陈旧写者改状态 |
| **未知副作用冻结** | 不确定就停下核对，不假装成功 |
| **证据按独立任务计数** | 一个任务反复自修不能堆出「经验」 |
| **检查点带环境** | 模板变了就不是合法回滚点 |

### 需要你决策的三处

**A. 要不要现在部署到你的环境？**
这是 ①。部署后真实样本才会开始积累，自循环才会第一次真正转起来。但会动到你正在用的 DSH。

**B. 慢循环用什么模型？**
这是 ②。没有 Jev 凭据，双循环的「慢」这一半始终是设计态。你可以给凭据，或者明确「先用规则路径跑通真实任务，Jev later」。

**C. 第一件真实任务是什么？**
这是 ④。现在能描述任意任务，但没有任何真实活流过。你给我一个具体场景，它立刻能产生第一批真实样本。

## 六、一句话总结方向

**架构是对的，卡点不在设计，在「没有接到你真实使用的环境里」。**

现在已经能做到：任意任务运行时描述 → 自动生成配方 → 单步/多步/分支 → 每步独立验收 → 失败可修复 → 全过程可追溯。

但这些都是**在隔离树里对着测试证明的**，不是**在你的工作流里跑出来的**。要让「自循环迭代」名副其实，必须跨过中间那个 ❌。

# Existing host invocation evidence boundary

The inspected `@deepseek-ai/dsh-tools` 0.2.2-rc.5 source appends a session-scoped `tool/call` sequence during batch settlement and separately creates an execution token when preparing a tool. A public one-to-one token-to-sequence binding was not identified. Session sequence numbers and turn or step values locate records only within their session; they do not establish a logical task identity or authenticate a caller. A skipped call may have a synthetic call and result without a tool body invocation. Concurrent calls may settle in a different order, and `callId` is not a unique key.

PTC nested dispatch has its own start and settlement events. An agent, session log, start event or valid ancestry can be absent, and queued calls abandoned before start can be unlogged. Event notifications and close timestamps alone do not establish a synchronized authoritative association. These observations are limited to the inspected version and must be checked against the actual running host.

A bounded read-only review of a natural SAG test repair found prior writes, indexing, recalls and reads for the existing `capabilities/sag-cli.md` object, but no execution or adoption signal in that object's trace. Another memory-manager object had historical positive and correction signals whose origin was unauthenticated and which were not linked to that repair. The runtime task list was empty in the queried scope, and the repair-event store was unavailable. None of these observations proves that evidence or use is absent elsewhere, or that the task formed a growth loop.

Existing signals and event metadata can guide further investigation. Actual use, independently checked outcome, human adoption and principle attribution remain separate questions. Missing, inaccessible, ambiguous or unauthenticated evidence remains unknown and must not be promoted to governance evidence merely because records share an identifier or timestamp. The independent repair-evidence boundary is described in [repair-evidence-contract.md](repair-evidence-contract.md).
